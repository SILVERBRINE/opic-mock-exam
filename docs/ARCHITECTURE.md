# Architecture

## 목표

이 프로젝트는 서버를 운영하지 않고도 OPIc 말하기 연습을 제공하는 단일 페이지 앱입니다. 모든 세션 상태와 질문 편집 데이터는 사용자의 브라우저에 저장되며, 선택한 평가 방식에 따라 음성 전사와 피드백 경로가 달라집니다.

## 런타임 구성

### 음성·입력 계층

- `SpeechSynthesisUtterance`: 기본 브라우저 질문 음성을 재생합니다.
- `kokoro-js` + `onnx-community/Kokoro-82M-v1.0-ONNX`: 선택 시 Kokoro TTS를 브라우저의 WebGPU 또는 WASM에서 실행합니다. 가능한 환경에서는 Blob URL Web Worker를 최대 8개까지 준비해 추론과 WAV 변환을 병렬 처리하고, 메모리 부족·Worker 오류·미지원 브라우저에서는 건강한 슬롯만 유지하거나 메인 스레드 호환 모드로 전환합니다. 모델은 처음 준비할 때만 내려받고 이후 브라우저 캐시를 재사용합니다.
- 문항 음성 방식의 `녹음본`은 Kokoro가 만든 WAV를 문항별로 IndexedDB에 저장해 다음 재생부터 파일처럼 재생합니다. 버튼으로 200문항을 한 번에 미리 만들거나, 필요한 문항만 첫 재생 때 생성할 수 있습니다. 200문항 일괄 생성은 PC 사양과 브라우저에 따라 30분 이상 걸릴 수 있으며, 처리 오버레이에 `0/200`부터 현재 진행 상황을 표시합니다. Worker 결과는 메인 스레드에 도착한 뒤 WAV 구조·신호를 빠르게 검증하고 저장합니다.
- `MediaRecorder`: 답변 원본을 녹음합니다. API·Whisper 경로에서는 브라우저 음성인식을 중복 실행하지 않고 녹음 원본만 종료 후 전사합니다.
- `getUserMedia`: 세션에서 하나의 마이크 스트림을 재사용해 문항마다 권한을 다시 요청하지 않도록 합니다.
- 모의고사 질문은 문항당 최대 2회 재생하고, 연습모드 질문은 반복 재생을 허용합니다. 재생 횟수와 전사된 답변 텍스트는 브라우저 저장소에 기록합니다. 사용자의 답변 녹음 원본은 전사 요청이 끝나면 메모리에서 해제하며 파일로 저장하지 않습니다.

### 전사 계층

문항당 시간은 180초이며 녹음 종료 요청 시 즉시 일시 정지합니다. 연습 종료는 답변과 피드백이 존재하고 녹음·전사·평가 작업이 모두 끝난 경우에만 허용합니다. Gemini 전사는 빈 응답·출력 한도 종료를 한 번 재시도합니다. 실패한 오디오는 현재 탭 메모리에 보관하여 재전사할 수 있으며, 실패 사유를 표시하고 무응답 0점 처리를 막습니다. 새로고침하면 이 오디오 메모리는 사라집니다.

1. 로컬 Whisper가 준비되면 `whisper.cpp` WASM과 `ggml-base.en-q5_1.bin`을 사용합니다.
2. OpenAI 선택 시 `/v1/audio/transcriptions`의 `gpt-4o-mini-transcribe`를 사용합니다.
3. Gemini 선택 시 Gemini Flash의 오디오 입력을 사용합니다.
4. 브라우저 음성 인식은 Whisper를 준비하지 않은 오프라인 기본 평가에서만 실시간 대체 입력으로 사용합니다. API·Whisper 경로는 녹음 원본을 선택한 전사기로 처리합니다.

Whisper 모델은 IndexedDB에 캐시되며, 실제 추론은 브라우저의 WASM 런타임에서 수행됩니다. 최초 준비 때 `ggml.ai`의 whisper.cpp 실행 파일과 Hugging Face의 모델 파일을 내려받으므로 완전한 에어갭 오프라인 실행은 아닙니다. 이후에는 캐시된 모델을 재사용합니다. GitHub Pages에서는 `coi-serviceworker.js`가 COOP/COEP를 보완해 `SharedArrayBuffer` 기반 WASM을 실행하고, `full_default`의 비동기 worker가 끝난 뒤 출력 결과를 읽습니다. 실행 파일은 현재 페이지 컨텍스트에서 동작하므로, 이 외부 파일을 신뢰할 수 없는 복사본으로 바꾸지 않아야 합니다. 최대 3분 답변을 처리할 수 있도록 녹음 종료 후 오디오를 16kHz mono PCM으로 변환합니다.

### 평가 계층

- 규칙 평가: 단어 수, 문장 구성, 연결어, 어휘 반복, 멈춤 신호를 계산합니다.
- 로컬 LLM: WebGPU가 가능한 환경에서만 선택적으로 실행되며 규칙 평가를 보조합니다.
- 온라인 AI: OpenAI 또는 Gemini 응답은 JSON 평가 형식으로 정규화합니다.
- Gemini Auto: 사용 가능한 Flash 모델을 문항 단위로 순환하고, 한 문항의 전사·채점 모델은 고정합니다. 429·권한 오류·시간 초과는 다음 모델로 재시도합니다.
- Gemini 3 계열은 `temperature`를 보내지 않고 낮은 `thinkingLevel`을 사용하며, Gemini 3.1 Pro처럼 `minimal`을 지원하지 않는 모델은 `low`로 조정합니다. Gemini 2.5 Flash만 `thinkingBudget: 0`을 사용하고 Pro에는 해당 설정을 보내지 않습니다.
- Gemini 응답은 사고용 파트를 제외한 최종 텍스트만 읽고, JSON 코드블록·앞뒤 설명·trailing comma를 정리합니다. 파싱에 실패하면 응답 종료·차단 사유를 기록하고 한 번 재요청합니다.
- 온라인 평가 실패 시 해당 문항은 규칙 평가로 안전하게 대체합니다.

온라인 평가는 모델마다 표현력 차이가 있으므로, 같은 영어 프롬프트·1~10 네 기준·총점 산식으로 정규화합니다. Auto는 계정 전체 할당량을 읽을 수 없어서 현재 탭에서 관찰한 요청만 보수적으로 추적하는 방식입니다.

평가 작업은 `evaluationJobs`와 `transcriptionJobs`로 추적하고, 전체 화면 처리 오버레이를 띄우지 않은 채 다음 문항을 푸는 동안 완료되도록 비동기 처리합니다. 제출 시점에는 남은 작업을 마무리한 뒤 답변이 저장된 문항만 평균에 포함합니다.

## 저장 데이터

| 데이터 | 저장 위치 | 목적 |
| --- | --- | --- |
| 진행 상태·답변·피드백 | `localStorage` | 중단 후 재개 |
| 질문 편집 내용 | `localStorage` | 사용자별 질문 목록 유지 |
| Whisper 모델 | `IndexedDB` | 약 57MB 모델 재다운로드 방지 |
| Kokoro 질문 모델 | Transformers.js 브라우저 캐시 | 약 86MB 양자화 모델 재다운로드 방지 |
| 질문 녹음본 | `IndexedDB` (`opic-tts-cache-v1`) | Kokoro WAV를 문항별로 캐시해 녹음본처럼 재생 |
| 연습 히스토리 | `localStorage` | 문항·답변·평가 기록 유지 및 JSON 백업/복원 |
| API 키 | 메모리와 `sessionStorage` | 같은 탭의 새로고침 후 복원, 명시적 삭제 지원 |

API 키와 연결 정보는 제공자별로 `sessionStorage`에 보관합니다. 같은 탭의 새로고침과 평가 방식 변경 후에도 복원하며, 키 삭제 버튼은 메모리와 세션 저장소를 함께 지웁니다. 브라우저의 탭 복원 기능은 세션도 복원할 수 있으므로 공용 PC에서는 키 삭제를 사용합니다. API 방식에서는 음성 전사와 답변 텍스트가 선택한 제공자(OpenAI 또는 Google)로 직접 전송됩니다.

기존 버전이 `localStorage`에 남긴 API 키와 핸드셰이크 정보는 앱을 업데이트한 뒤 첫 실행에서 자동으로 삭제합니다. 공용 PC에서는 사용 후 브라우저 탭을 닫고 API 제공자의 사용량·키 제한도 확인하세요.

히스토리 저장 키는 버전 업데이트에서도 유지됩니다. Pages 주소가 바뀌거나 새 HTML을 다른 브라우저에서 열 경우에는 앱의 JSON 백업/복원 기능으로 기록을 옮깁니다.

## 배포

GitHub Pages와 같은 정적 호스팅에 `index.html`을 게시할 수 있습니다. 마이크와 WASM 권한 문제를 줄이기 위해 HTTPS 또는 `localhost` 환경을 사용합니다. 별도 서버가 없기 때문에 서버 측 사용자 계정, 개인별 사용 기록, 서버 로그 기반 분석은 제공하지 않습니다.
