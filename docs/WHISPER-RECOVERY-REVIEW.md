# v1.4.3 Whisper 중단 처리

사용자 화면의 `Aborted(). Build with -sASSERTIONS`는 Whisper WASM 실행 중단이다. v1.4.2의 LLM 출력 검증과 다른 경로이며 화면만으로 메모리 부족, 스레드 오류, 장치별 런타임 결함 중 하나를 확정할 수 없다.

기존 코드는 전사 시간 초과만 런타임 장애로 기억했다. WASM abort 뒤에도 준비 완료 상태와 재시도 버튼이 남아 중단된 엔진을 계속 호출할 수 있었다.

## 변경

- Emscripten onAbort, 동기 예외, 비동기 출력의 abort·메모리 오류를 감지한다. 즉시 Whisper 준비 상태를 해제하고 손상된 엔진을 격리한다.
- 긴 PCM 입력을 최대 30초씩 순차 처리하고 스레드를 최대 2개로 제한한다. 자원 압박을 낮추는 조치이며 모든 장치의 abort 방지를 보장하지 않는다. 분할 경계에서 문맥이 끊길 수 있으며 분할별 타임스탬프로 전체 멈춤 횟수를 추정하지 않는다.
- 어느 구간에서든 실패하면 부분 전사를 반환하지 않고 녹음 전체를 복구 대상으로 유지한다. 장애 이후 동일 엔진 재호출을 차단한다.
- 복구 화면에서 원본 파일 저장 또는 사용자가 선택한 API 전사로 이동할 수 있다. API 복구는 사용자의 키 연결 및 재전사 조작 후 수행한다. 녹음 원본은 현재 탭 메모리에 있으므로 새로고침 전 파일로 저장해야 한다.

## 검증

자동 테스트: 75초 PCM의 30/30/15초 분할, 최대 2스레드, 두 번째 구간 abort, 부분 답변 미저장, 원본 보존, 재시도 차단, API 복구 전환, 비동기 abort 출력 감지.

실제 Whisper 테스트는 공개 JFK 음성 샘플과 이를 반복한 66초 PCM의 분할 실행을 완료했고, 인터넷 차단 후 캐시된 실행 파일·모델로 재전사도 확인했다. 반복 샘플은 처리 완료 검사이며 전체 단어 정확도를 입증하지 않는다. 사용자 기기의 동일 abort를 재현한 것은 아니며 오류 주입 테스트는 복구 동작을 검증한다.
