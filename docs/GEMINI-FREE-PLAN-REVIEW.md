# Gemini 무료 플랜 운용

## 구현된 기본 흐름

API 모의고사는 문항마다 녹음 원본을 전사하고 다음 문항으로 이동한다. 전체 제출에서 전사 완료를 기다린 뒤 미채점 답변을 5개씩 일반 API 요청으로 채점한다. OpenAI와 Gemini에 동일하게 적용하며 연습모드의 즉시 피드백은 유지한다. Google의 비동기 Batch API를 사용하는 것은 아니다.

15문항에 재시도·연결 확인을 제외하면 전사 15회 + 채점 3회 = 18회다. 기존 문항별 전사·평가 30회보다 요청 수가 40% 줄어든다. 답변 입력 토큰은 남으므로 TPM이나 비용도 40% 줄어든다는 의미는 아니다. 공통 평가 지침은 묶음마다 한 번만 전송한다.

응답은 정확한 문항 번호, 네 정수 점수(1~10), 비어 있지 않은 개선점을 요구한다. 누락·중복·잘못된 번호·잘린 응답은 거부한다. 성공한 묶음은 즉시 저장하고 실패 시 전체 제출로 미완료 답변만 재시도한다. 답변이 변경되면 이전 채점을 재사용하지 않는다. 실패를 규칙 점수로 대체하지 않으며 완료 전 총점을 확정하지 않는다. 저장소가 차단되면 기존 메모리 저장 안내가 적용된다.

최대 2문항을 명시적으로 건너뛸 수 있고 해당 문항은 채점 요청·분모에서 제외한다. 미응답과 API 장애는 구분한다.

## Gemini Auto

- 후보는 연결된 목록의 `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite` 두 개뿐이다. 요청마다 교대하며 다른 Flash 모델로 확장하지 않는다. 하나만 제공되면 그 후보만 사용한다.
- 오류 시 짧은 지수 대기·지터 후 다른 가용 후보를 시도한다. 모두 막히면 저장된 답변으로 나중에 재시도한다. 503은 서버 가용성 오류이며 일일 한도 초과와 동일하지 않다.
- 사용자가 제시한 계정 한도에 맞춰 두 후보의 탭 내부 제한을 RPM 15, 최근 24시간 500회로 설정했다. 공급자 잔여량 조회가 아니며 다른 탭·프로그램의 요청을 모른다. 실제 한도와 계정 권한은 AI Studio와 API 응답이 기준이다. 새로고침해도 공급자 한도는 초기화되지 않는다.
- 동일 루브릭과 점수 검증을 사용하고 실제 모델을 문항별 결과에 기록한다. 동일 지침만으로 모델 간 일관성이나 공식 OPIc 채점 정확성이 보장되지는 않는다.

## 녹음과 멈춤

API·준비된 Whisper 경로는 SpeechRecognition을 동시에 열지 않고 MediaRecorder와 살아 있는 마이크 스트림을 재사용한다. 무음 관찰은 녹음 종료 조건이 아니다. 브라우저 인식 서비스 종료·오류는 원본 녹음을 유지하며 자동 재시작으로 권한을 반복 요청하지 않는다. 부분 전사를 완성 답변으로 채점하지 않고 원본을 복구 대상으로 보관한다. 사용자 중지 또는 문항 시간 종료 시 녹음을 정리한다. 실제 장치 분리·OS 권한 취소까지 방지할 수는 없다.

## Transcribe Live 검토 — 아직 미연동

`gemini-3.5-transcribe-live`는 공식 실시간 STT 모델이고 무료 구간이 있다. WebSocket으로 16kHz 모노 PCM을 보내므로 현재 녹음 파일 업로드와는 별도 전송 구현이 필요하다. 세션당 최대 10분이며 전체 모의고사는 연결 갱신 또는 문항별 세션이 필요하다. 한도 표의 RPM/RPD 무제한이 TPM·연결 시간·가용성까지 무제한이라는 뜻은 아니다.

도입 시 `VERBATIM` 모드를 유지해야 한다. `SMART`는 필러와 비유창성을 제거하므로 연습 평가에 적합하지 않다. 원본 녹음은 별도로 유지하고 연결 손실 시 기존 파일 전사로 복구하는 경로가 필요하다.

## 검증 및 공식 자료

Edge 자동 테스트: 제출 전 채점 0회, 5문항 묶음, 번호 중복 거부, 성공 묶음 재사용, 지정 모델 교대, 다른 모델 제외, 마이크 권한 호출 1회 및 스트림 재사용, 브라우저 인식 중단 시 녹음 유지, OpenAI 응답 검증. 모의 API 응답을 사용하며 실제 개인 키의 무료 한도·음성 정확도는 검증하지 않았다.
