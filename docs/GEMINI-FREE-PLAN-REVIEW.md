# Gemini 무료 플랜 효율 검토

## 확인된 원인

- 제공된 화면의 503은 서버 가용성 문제다. 이 오류만으로 무료 일일 한도 소진이라고 판단할 수 없다.
- 현재 Auto는 문항별로 모델을 순환하지만 전사에 성공한 모델을 해당 문항 평가에도 먼저 사용한다. 최대 3개 후보와 90초 상한이 있어 모든 후보가 실패하면 임시 평가가 남을 수 있다.
- 클라이언트가 모든 모델에 분당 4회·최근 24시간 18회 상한을 적용한다. 이는 실제 공급자 한도를 조회한 값이 아니며, Flash-Lite처럼 계정에서 더 높은 한도를 가진 모델도 덜 사용할 수 있다.
- 현재 사용량은 탭의 관찰치다. 다른 탭·프로그램의 요청을 알 수 없고, 재연결/새로고침으로 추적 상태가 바뀐다. 계정 전체 잔여 무료량으로 표시하면 안 된다.
- 임시 규칙 점수를 실제 점수와 평균내는 것은 잘못된 인상을 준다. 이번 수정에서는 총점·등급을 보류하고 명시적으로 건너뛴 최대 2문항만 분모에서 제외한다.

## 권장 구조 — 검토안, 아직 묶음 채점 구현 전

1. 모의고사 진행 중에는 전사만 수행하고 다음 문항을 풀게 한다. 연습모드는 즉시 피드백을 유지한다.
2. 제출 시 유효한 답변을 3~5개씩 묶어 일반 generateContent 요청으로 채점한다. 같은 시험에서는 가능하면 같은 채점 모델과 평가 기준 버전을 사용한다.
3. 응답에는 문항 ID와 점수·질문 충족 근거·구체적 오류를 필수로 요구한다. ID 누락·중복·범위 오류를 검사하고 실패한 묶음만 재시도한다. 성공한 묶음은 재요청하지 않는다.
4. 전사는 사용자가 확인한 무료 한도가 충분한 Flash-Lite를 우선 후보로 고려하고, 평가에는 검증된 Flash를 우선한다. 목록에 표시된다는 이유만으로 무료 호출 권한이나 한도를 보장하지 않는다.
5. 선택 가능한 절약 모드에서는 준비된 로컬 Whisper로 전사하고 Gemini는 제출 후 채점만 담당한다. 전사 공급자와 채점 공급자를 분리하는 UI가 필요하다. 이는 현재 자동 적용하지 않는다.

### 정상 경로 요청 수 예시

15문항, 재시도 없음, 묶음당 5문항을 가정한다.

| 방식 | 전사 | 평가 | 합계 |
|---|---:|---:|---:|
| 현재 문항별 API 전사·평가 | 15 | 15 | 30 |
| API 전사 + 제출 후 묶음 평가 | 15 | 3 | 18 |
| 로컬 Whisper + 제출 후 묶음 평가 | 0 | 3 | 3 |

묶음 평가는 RPD/RPM 요청 수를 줄이는 효과가 있다. 총 답변 토큰은 여전히 입력되므로 TPM이나 비용이 같은 비율로 감소한다고 보장하지 않는다. 전체 15개를 한 요청에 넣을 수도 있으나 출력 잘림·긴 대기·전체 재시도 위험 때문에 먼저 3~5개 묶음으로 검증하는 편이 적합하다.

Google의 별도 Batch API는 목표 처리 시간이 24시간인 비동기 작업이다. 시험 직후 결과가 필요한 이 앱에서는 일반 API 요청에 여러 답변을 넣는 방식을 권장한다.

## Auto 개선 방향

- 확인된 한도는 사용자 설정으로 입력하거나 공급자 오류의 Retry-After/RetryInfo를 반영한다. 키를 바꿔도 같은 프로젝트 한도가 늘어나지 않는다.
- 429는 모델별 일시 정지 및 안내, 503은 짧은 지수 대기와 다른 가용 후보 전환으로 다룬다. 재시도 총 횟수·시간은 제한한다.
- 모델별 성공·실패와 목적(전사/채점), 시도 순서를 표시한다. 키·녹음 원문은 진단 기록에 넣지 않는다.
- 채점 모델 변경이 필요하면 변경 사실을 결과에 기록한다. 동일한 프롬프트만으로 모델 간 점수 일관성이 보장되지는 않는다. 별도 전문가 기준 답변으로 보정·평가해야 한다.
- 채점 API 장애는 미채점 상태로 보존하고 사용자 요청 시 미완료 묶음만 다시 채점한다. 장애를 낮은 실력 점수로 대체하지 않는다.
- 전사에 설명문이나 번역 지시처럼 보이는 문장이 섞인 경우 원음을 확인해야 한다. 내용만 보고 실제 발화인지 모델이 덧붙인 것인지 확정하거나 임의 삭제하면 안 된다. 제출까지 녹음을 탭 메모리에 보관하고 재전사하는 복구 경로를 추가 검토한다.

## 공식 자료

- [Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits): RPM/TPM/RPD, 프로젝트 단위 제한, 실제 한도는 AI Studio에서 확인.
- [Troubleshooting](https://ai.google.dev/gemini-api/docs/troubleshooting): 429·503 재시도의 지수 대기와 지터, 최대 재시도 제한.
- [Batch API](https://ai.google.dev/gemini-api/docs/batch-api): 목표 처리 시간 24시간인 비동기 API.

## 이번 코드 변경

2문항 건너뛰기·복원·분모 제외, 미응답 0점, 임시 평가 총점 보류, Auto 오류 후 짧은 지수 대기 및 시도 모델 목록 표시. 묶음 채점·전사 공급자 분리·사용자 한도 설정은 위 검토안이며 현재 구현했다고 표시하지 않는다.
