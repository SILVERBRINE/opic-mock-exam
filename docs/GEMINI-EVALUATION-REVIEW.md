# Gemini 평가 오류 검토

## 확인된 문제

- 화면의 오류는 API 설정 자체가 로컬 모드로 변경된 것이 아니라 해당 문항의 온라인 평가 실패 후 규칙 평가를 사용한 결과다.
- 기존 요청은 JSON MIME 형식만 지정하고 필수 점수 필드 스키마를 보내지 않았다. 빈 응답, 누락 필드, 잘린 출력은 파싱 실패로 이어질 수 있다.
- 기존 오류 정보만으로 실제 실패 원인이 토큰 제한인지, 차단인지, 잘못된 스키마인지 구분할 수 없었다. 당시 API 원문은 확보하지 못했으므로 특정 원인을 확정하지 않는다.
- 규칙 평가가 길이와 연결어를 근거로 내용·유창성·문법에 10점을 부여할 수 있었다.
- 최종 결과는 실제 평가 출처 대신 선택된 모드로 채점 방식을 표시했다.

## 변경

- Gemini 요청에 필수 점수 4개와 개선 문장의 responseSchema를 추가했다.
- 출력 예산은 4096, 재시도는 8192로 늘렸다. 이는 최대 허용치이며 실제 사용량은 응답에 따라 달라진다.
- MAX_TOKENS 응답은 JSON처럼 보여도 채점에 사용하지 않는다. 비정상 JSON과 잘린 응답은 한 번만 재시도한다. 안전 차단은 재시도하지 않는다.
- 최종 텍스트와 thought 부분을 분리하고 종료 사유, 응답 길이, 출력·사고 토큰 수를 오류에 포함한다. 원문 답변이나 키를 진단에 추가 저장하지 않는다.
- 실패 시 API 선택을 유지하며 해당 문항의 대체 평가임을 본문에 표시한다.
- 규칙 점수의 내용·유창성·문법은 최대 5점으로 제한한다. 이 제한은 공식 채점 기준이 아니라 근거 없는 고득점을 방지하는 임시 정책이다.
- 문항별 평가 결과와 출처를 진행 데이터에 보존하고 최종 화면에 반영한다. 임시 규칙 평가가 포함되면 예상 등급을 판정 보류한다.

## 검증

`node scripts/session-regression.cjs` 실행 성공. Edge 가상 마이크의 실제 MediaRecorder와 모의 HTTP 응답을 사용했다.

- 세션 키 유지, 모드 전환, 타이머 정지, 조기 제출 방지
- 빈 전사 응답, 녹음 보존, 전사 재시도와 평가 완료
- HTTP 429 모델 전환
- 요청 스키마·출력 예산, MAX_TOKENS 후 성공, thought 필터링
- 반복된 필수 필드 누락 후 제한된 재시도와 임시 평가 표시
- 안전 차단 시 재시도 금지, 잘못된 점수 거부
- 임시 평가의 최종 출처 및 등급 판정 보류 표시
- 브라우저 런타임 오류 없음

실제 개인 Gemini 키 호출과 실제 사람 음성의 채점 정확도는 이 테스트로 검증하지 않았다. 생성 모델의 판단 정확성은 별도의 정답·전문가 평가 자료가 필요하다.
